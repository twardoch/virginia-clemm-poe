### Browser Landscape Analysis (macOS, OAuth-Capable, Non-Interfering)

Running browser automation on macOS that satisfies both **OAuth / anti-bot compliance** and **zero focus interference** requires overcoming two distinct operating-system and security constraints:

1. **The OAuth / Anti-Bot Dilemma:** Automated browsers running in standard headless mode (`--headless` or `--headless=shell`) leak automation fingerprints (such as `navigator.webdriver = true`, missing audio/video codecs, WebGL SwiftShader renderers, and CDP evaluation artifacts). Identity providers—most notably Google OAuth (`accounts.google.com`) and Cloudflare Turnstile (used by Poe)—detect these signals and abort with `"This browser or app may not be secure"` or infinite challenge loops.
2. **The macOS Focus-Stealing Dilemma:** macOS `WindowServer` activates any GUI application launched in standard headed mode (`[NSApp activateIgnoringOtherApps:YES]`). Opening windows or new tabs brings the browser to the foreground, switches macOS Spaces, bounces the Dock icon, and interrupts active typing in editors or terminals.

```python
from typing import Any
from playwright.sync_api import Browser as PlaywrightBrowser, Playwright as SyncPlaywright
from playwright.async_api import Browser as AsyncPlaywrightBrowser, Playwright as AsyncPlaywright

from ..config import PlaywrightAuthorConfig
from ..utils.paths import data_dir as get_data_dir


class CamoufoxEngineAdapter:
    def __init__(self, config: PlaywrightAuthorConfig, profile: str, verbose: bool):
        self.config = config
        self.profile = profile
        self.verbose = verbose
        self.profile_dir = get_data_dir() / "profiles" / profile / "camoufox"
        self.profile_dir.mkdir(parents=True, exist_ok=True)

    def _get_camoufox_kwargs(self) -> dict[str, Any]:
        is_headless = self.config.browser.headless_mode in ("headless", "quasi")
        return {
            "headless": is_headless,
            "os": "macos",
            "enable_cache": True,
            "window": (
                self.config.browser.viewport_width,
                self.config.browser.viewport_height,
            ),
        }

    def start(self, playwright: SyncPlaywright) -> PlaywrightBrowser:
        try:
            from camoufox.sync_api import Camoufox
        except ImportError as e:
            raise ImportError(
                "Camoufox engine requires 'camoufox'. Install via: uv add 'camoufox[geoip]'"
            ) from e

        browser_manager = Camoufox(
            playwright=playwright,
            persistent_context=False,
            **self._get_camoufox_kwargs(),
        )
        return browser_manager.__enter__()

    async def start_async(self, playwright: AsyncPlaywright) -> AsyncPlaywrightBrowser:
        try:
            from camoufox.async_api import AsyncCamoufox
        except ImportError as e:
            raise ImportError(
                "Camoufox engine requires 'camoufox'. Install via: uv add 'camoufox[geoip]'"
            ) from e

        browser_manager = AsyncCamoufox(
            playwright=playwright,
            persistent_context=False,
            **self._get_camoufox_kwargs(),
        )
        return await browser_manager.__aenter__()

```

#### 5. Background Tab Initialization in Context Helper (`author.py`)

When creating pages via CDP, instruct the browser target manager to keep the tab in the background:

```python
# this_file: src/playwrightauthor/author.py (excerpt inside get_page definition)


async def _get_non_intrusive_page(context):
    """Create or retrieve a page using CDP background target to prevent focus-stealing."""
    pages = [p for p in context.pages if not p.url.startswith("chrome-extension://")]
    if pages:
        return pages[0]

    # Create target in background via CDP session
    cdp = await context.new_cdp_session(pages[0] if pages else context)
    target = await cdp.send(
        "Target.createTarget", {"url": "about:blank", "background": True}
    )

    for page in context.pages:
        if page._guid == target.get("targetId"):
            return page
    return await context.new_page()

```

# Headless OAuth browsers on macOS for playwrightauthor and virginia-clemm-poe

Oct 22, 2026 · @Fontlab Ltd

## Summary

Keep Chrome for Testing (CfT) as the primary browser. Add two new launch modes for the same CfT binary and the same profile: `headless` (Chrome's new headless mode, no window) and `hidden` (a normal window in a Dock-less app copy that macOS keeps hidden). Do the OAuth sign-in once in the existing `headed` mode. All later runs reuse the stored session without a window. Add Camoufox (Firefox) as an optional engine for sites that block Chromium. Do not adopt Lightpanda, WebKit, branded Google Chrome or chrome-headless-shell for this work.

The change is mostly in playwrightauthor. virginia-clemm-poe gets a small adapter, a `login` command and a `--browser-mode` flag.

Before the new modes, fix five defects that cause interference today (section "Current state"). One of them can kill a browser that another profile or another tool started.

| Mode | Browser | Window | Use it for | OAuth |
| --- | --- | --- | --- | --- |
| `headed` (exists) | CfT | Visible, takes focus | First sign-in, captcha, consent | User signs in here |
| `headless` (new, default for scripts) | CfT with `--headless=new` | None | Scheduled runs, `virginia-clemm-poe update` | Reuses the stored session |
| `hidden` (new) | CfT agent copy (`LSUIElement`) | Exists, hidden, no Dock icon | Sites that reject headless Chrome | Reuses the stored session |
| `camoufox` engine (new, optional) | Firefox fork | None | Fallback when Chromium is blocked | Own profile, own sign-in |

## Current state

playwrightauthor starts CfT as a detached subprocess with `--remote-debugging-port` and a per-profile `--user-data-dir`, then attaches Playwright with `connect_over_cdp`. Profiles get stable ports from 9222 upward (`state_manager.get_profile_debug_port`). The engine registry (`engine.py`) knows two engines: `chrome` (CfT) and `cloak` (CloakBrowser). The user signs in once in the visible window; later runs reuse the cookies in the profile. virginia-clemm-poe calls `AsyncBrowser` from its `BrowserManager` and runs a `BrowserPool` of up to 3 connections during `update`.

The code review found these defects. Each one causes interference or blocks unattended runs.

| # | Where | Defect | Effect on the user |
| --- | --- | --- | --- |
| D1 | `browser_manager.ensure_browser` + `process.get_chrome_process()` | When no CfT listens on this profile's port, it kills the first process whose path matches `chrome for testing`, `chrome-mac-`, `chromium-` or `cloakbrowser`. It does not check the port or the profile. | Starting profile `default` kills a running profile `work`, or a CfT/Playwright Chromium that another tool started. |
| D2 | `engines/chrome.py` → `launch_chrome` | `BrowserConfig.headless` and `PLAYWRIGHTAUTHOR_HEADLESS` exist, but the chrome engine never adds a headless flag. Only the cloak engine reads them. | Every run opens a visible window that takes focus. |
| D3 | `Browser.__enter__` / `AsyncBrowser.__aenter__` → `notify_interactive_task` | A modal dialog opens on every session start unless `suppress_dialog=True`. virginia-clemm-poe never sets it. | One modal dialog per pool connection during `update` and `balance`. |
| D4 | `engines/cloak.py` | Uses `config.browser.debug_port`, not the per-profile port. | Two cloak profiles collide on port 9222. |
| D5 | virginia-clemm-poe `PoeSessionManager.login_with_browser` | Signs in inside `browser.new_context()`. That context is not part of the persistent profile. | The sign-in is lost from the profile; only `poe_cookies.json` keeps it. |

Three further issues in virginia-clemm-poe matter for headless work:

- `BrowserManager` accepts `debug_port` but does not use it, and always uses profile `default`. Poe shares the profile with every other script that uses the default.
- Each pooled `BrowserConnection.get_page()` checks for `browser.get_page`. Only the sync `Browser` attaches it; `AsyncBrowser` does not. The pool therefore falls back to `context.new_page()`, and `BrowserManager.get_page()` and `BrowserPool.get_reusable_page()` fail with `BrowserManagerError`.
- Issue 302 reports four "Something went wrong when opening your profile" dialogs after `balance`. This is consistent with several processes opening one profile, or with a Keychain access failure. Section "OAuth strategy" removes both causes.

## Isolation techniques on macOS

Use four layers together: a separate app identity, a separate profile, no visible window, and strict process ownership. Each row below is a technique the spec uses or rejects.

| Technique | What it prevents | Cost and limits | Use in |
| --- | --- | --- | --- |
| Separate bundle ID (CfT is `com.google.chrome.for.testing`) | Collision with the user's daily Chrome: Dock icon, AppleScript target, Keychain item, `open -a` routing | None; already in place | All modes |
| One `--user-data-dir` per profile under playwrightauthor's data dir | Access to the user's real profiles. Required for branded Chrome since Chrome 136. | None; already in place | All modes |
| `--headless=new` | Any window, menu bar change or focus change | Sites can detect headless. The default user agent contains `HeadlessChrome`, also in the `sec-ch-ua` header, and `Accept-Language` is missing ([Castle](https://blog.castle.io/how-to-detect-headless-chrome-bots-instrumented-with-playwright/)). Mitigate in "OAuth strategy". | `headless` |
| Agent app copy: copy the CfT `.app`, set `LSUIElement` to true in `Info.plist`, set a new `CFBundleIdentifier`, ad-hoc re-sign | Dock icon, menu bar takeover, Cmd-Tab entry | Edits break the Google signature. The launcher already re-signs ad-hoc (`_self_heal_macos_codesign`). The new identity gets its own Keychain and preferences domain. | `hidden` |
| Hide the app after launch: `NSRunningApplication(processIdentifier=pid).hide()` through PyObjC | Visible windows of the agent copy | Apple documents that "a hidden app may unhide itself at any time" ([Apple](https://developer.apple.com/documentation/appkit/nsrunningapplication.md)). | `open -g -j` launch | Foreground activation at launch | `-j` ("launches the app hidden") is a request only; reports show apps ignore it ([Apple forums](https://developer.apple.com/forums/thread/681163)). Does not pass `--args` reliably to a second instance. | Not used. The launcher keeps `subprocess` and hides by PID. |
| Off-screen window position (`--window-position=-10000,-10000`) | Visible window | macOS can move windows back onto a display. Unverified on current macOS. | Optional extra in `hidden`, test before relying on it |
| `--use-mock-keychain` | Keychain prompts. An ad-hoc re-signed app has a new code identity, so macOS asks again for the real Keychain item. | Cookies are encrypted with a fixed key, so the profile folder must be protected (mode 0700). Profile must always use the same setting, or its cookies become unreadable. Playwright's own launches use `--password-store=basic --use-mock-keychain` ([issue 32539](https://github.com/microsoft/playwright/issues/32539)). | All modes for new profiles |
| Throttle flags already set (`--disable-backgrounding-occluded-windows`, `--disable-renderer-backgrounding`, `--disable-background-timer-throttling`) | Slow or frozen pages in hidden windows | None | `hidden`, `headless` |
| Process ownership: record the PID and `--user-data-dir` of every browser the tool starts | Killing or attaching to processes the tool did not start (fixes D1) | Small state change | All modes |
| Per-profile file lock (`fcntl.flock` on `<profile>/.pa.lock`) | Two processes opening one profile (likely cause of issue 302) | Small | All modes |
| Virtual display (private `CGVirtualDisplay` API) | Visible window | Private API; can break with any macOS update | Rejected |
| Separate macOS user account | Everything | Heavy setup; Keychain and GUI session per user | Rejected |

## OAuth strategy

The user signs in only in a plain headed browser. Automation attaches only after the sign-in. Every later run is headless and first checks that the session is still valid. This is the pattern playwrightauthor already uses, and it is the common practice for Google accounts: start Chrome as a normal browser with a dedicated profile, sign in by hand, then attach Playwright over CDP; never sign in to Google from a Playwright-launched window ([example skill](https://skills.cat/skills/sunwood-ai-labs/logged-in-google-chrome-skill)). Google can block automated sign-ins as bot traffic ([Stably docs](https://docs.stably.ai/stably2/auth/auth-with-google)).

&#91;embedded content: session check and sign-in escalation · 2 decisions, 1 loop\]

A failed probe in an unattended run stops the run with `AuthRequiredError`. Only an attended run opens a window.

### Rules

1. **Sign-in happens headed.** `playwrightauthor login --profile P --service S` starts CfT without `--headless`, without `--enable-automation` and without Playwright's default arguments. The CDP port is open, but no script drives the page until the probe passes.
2. **One process per profile.** Before a mode switch, close the browser through CDP (`Browser.close`), wait until the process exits and the profile lock is free, then start the new mode. Chrome cannot open one `--user-data-dir` twice.
3. **Same Keychain mode in every mode.** New profiles always use `--use-mock-keychain`. The profile state records `keychain: mock | real`. The launcher refuses to start a profile with the other setting.
4. **Headed identity in headless runs.** At sign-in, read `navigator.userAgent` and `navigator.languages` from the headed window and store them in the profile state. Headless runs pass `--user-agent=<stored value>` and `--lang=<first language>`. This removes the `HeadlessChrome` token from the user agent and adds `Accept-Language`. Add `--disable-blink-features=AutomationControlled` in all modes so `navigator.webdriver` is false.
5. **Session probe per service.** A probe is a URL, the cookie names that must exist, and an optional selector that must appear. Example for Poe: URL `https://poe.com/`, cookies `m-b` or `p-b`, selector `button[aria-label='User menu']` (the selector `login_with_browser` already waits for). Example for Google: URL `https://myaccount.google.com/`, cookies `SID` and `__Secure-3PSID`. The probe timeout is 15 s.
6. **Escalation order.** If a headless probe fails because of a challenge page (Cloudflare or a Google "verify it's you" page) and not because of missing cookies, retry once in `hidden` mode before asking the user to sign in.
7. **No dialog without a window.** `notify_interactive_task` runs only when the launcher opens a visible headed window. This fixes D3 for all callers.
8. **OAuth popups.** "Sign in with Google" and "Sign in with Apple" can open a second window. In `headless` it is invisible. In `hidden` the watcher hides the app again within 250 ms. In `headed` it is shown on purpose.

## Architecture in playwrightauthor

The launch mode becomes a property of each session, separate from the engine. The engine decides which binary runs; the mode decides how its window behaves. The existing engine registry stays; the adapters get a `mode` argument and a richer return value.

### New types

```python
class LaunchMode(StrEnum):
    HEADED = "headed"      # visible window, used for sign-in
    HEADLESS = "headless"  # --headless=new, no window
    HIDDEN = "hidden"      # agent app copy, window hidden by PID

class Interactive(StrEnum):
    AUTO = "auto"      # escalate to headed only if a TTY or GUI session is present
    ALWAYS = "always"
    NEVER = "never"    # raise AuthRequiredError instead of opening a window

@dataclass(frozen=True)
class ServiceProbe:
    name: str
    url: str
    any_cookies: tuple[str, ...] = ()   # at least one must exist
    all_cookies: tuple[str, ...] = ()   # all must exist
    selector: str | None = None
    timeout_ms: int = 15_000

@dataclass
class Session:
    browser: Browser | None        # None for persistent-context engines (Camoufox)
    context: BrowserContext
    mode: LaunchMode
    owned_pid: int | None
    def get_page(self) -> Page: ...   # new page in context, never a shared existing tab
```

The adapter contract changes from `start(playwright_chromium) -> Browser` to `start(playwright, mode) -> Session`. `Browser.__enter__` keeps returning a Playwright `Browser` for CDP engines, with `get_page` attached as today. It also attaches `browser.session` for new callers. `get_page()` gets a `reuse: bool = True` argument. The default keeps the old "first existing tab" behaviour (R8). Concurrent callers pass `reuse=False` and get a new tab in the persistent context.

`AsyncBrowser.__aenter__` attaches an async `get_page()` with the same signature. Today only the sync class has it.

### Why the CDP port stays

The port lets the `browse` command keep one browser alive and lets other processes attach to it. Playwright's own `launch_persistent_context` would tie the browser lifetime to one Python process. The port binds to `127.0.0.1` only. Any local process of the same user can still attach; this risk exists today and is accepted. Attach with `connect_over_cdp(url, is_local=True, no_defaults=True)` so Playwright does not change the profile's default context.

### Migration of existing profiles

Existing profiles were created without `--use-mock-keychain`, so their cookies are encrypted with the real Keychain item of CfT. Starting them with mock Keychain makes the stored cookies unreadable, and the user must sign in again. Starting them without it from an ad-hoc re-signed bundle can show a Keychain prompt.

Rule: a profile without a `keychain` field in state is `real`. The launcher keeps `real` for it in all modes and prints a one-time notice that recommends `profile migrate`. `hidden` mode is not available for `real` profiles, because the agent bundle has a new identity and would always prompt. New profiles are `mock`.

## Risks, open questions and rollout

The main risk is detection: a site can accept the headed session and still reject the same cookies in headless Chrome. The `hidden` mode and the `challenge` probe result exist for that case.

| Risk | Effect | Mitigation |
| --- | --- | --- |
| Google, Cloudflare or Poe flag headless Chrome | Probe returns `challenge`; run stops | Headed user agent and language (rule 4); automatic retry in `hidden`; CloakBrowser or Camoufox as last resort |
| Chrome or macOS ignores `hide()` or reactivates the app | Window flashes, focus changes | Watcher re-hides; AC8 measures it; fall back to `headless` if AC8 fails on a macOS release |
| Mock Keychain stores cookies with a fixed key | Anyone who can read the profile folder can read the session | Profile folders mode 0700 inside the user's Library; document it; `keychain=real` remains possible for `headed`/`headless` |
| Playwright default headless path is `chrome-headless-shell` since 1.57 | A future refactor that uses `chromium.launch(headless=True)` breaks profile reuse silently | Unit test that the launcher never calls `launch()` for profile engines |
| CloakBrowser macOS builds above Chromium 145 need a Pro subscription; binary may not be redistributed | Free `cloak` engine ages | Keep optional; do not bundle |
| Camoufox headless is documented as detectable; no Xvfb on macOS | `camoufox` engine may fail on strict sites | Optional engine; `hidden` is not offered for it |
| Lock left by a crashed run | Profile reported busy | Lock is `flock`, released by the kernel on process exit; stale `SingletonLock` removed only when the owned PID is dead |

# Invisible OAuth-capable browsers on macOS: implementation specification

**Date:** 22 October 2026  
**Targets:** `playwrightauthor` and `virginia-clemm-poe`  
**Platforms:** macOS Apple Silicon and Intel  
**Status:** researched design proposal; not implemented or smoke-tested against live OAuth providers.

## 1. Objective and non-goals

Provide persistent, authenticated browser automation without displaying windows, changing the frontmost macOS app, taking keyboard focus, or interfering with a person's normal browser sessions. Preserve the ability to open a dedicated interactive browser for explicit sign-in/consent/MFA. Support multiple browser engines with the minimum viable infrastructure, using Playwright wherever possible.

Non-goals: bypassing an identity provider's anti-automation requirements, extracting sessions from an ordinary personal browser, fingerprint spoofing by default, background interactive authentication without user consent, or requiring a macOS display server substitute.

**Key separation:** rendering an OAuth redirect/consent page is not the same as being *permitted* to authenticate through browser automation. Headless execution is for post-login sessions, and an OAuth provider may still reject a controlled browser even in headed mode. Where the application is itself a registered OAuth client, use an external system browser with PKCE rather than a Playwright-controlled identity-provider login. Where the website (such as Poe) owns the OAuth login flow, there may be no transferable OAuth token; reuse the website session in a dedicated profile only if the provider allows it.

## 2. Browser candidates as of October 2026

| Backend | macOS | True headless | Playwright interoperability | Authenticated site sessions | Recommendation |
|---|---|---|---|---|---|
| **Chrome for Testing, new headless** | Apple Silicon and Intel | Yes | Existing CDP connection, or Playwright native launch | Persistent user data directory; provider-dependent | **Default**; already in PlaywrightAuthor |
| **Playwright-managed Chromium, new headless** | Yes | Yes (`channel="chromium"`) | Native Playwright | Persistent context and storage state | First alternate; easy local testing |
| **Microsoft Edge** | Yes | Yes | Official Playwright `msedge` channel | Persistent context; provider-dependent | Optional mainstream alternative |
| **Playwright Firefox** | Yes | Yes | Native Playwright with patched Firefox | Persistent context; provider-dependent | **Independent-engine fallback** |
| **Camoufox** | Yes | Yes | Python package and compatible Playwright API; separate integration | Persistent context; provider-dependent | Optional, feature-gated; review dependency compatibility |
| **Existing private CloakBrowser** | Depends on locally available package/build | Configured in project's adapter | Existing CDP adapter | Existing per-profile directory | Keep as optional existing backend; verify on target Macs |
| **Playwright WebKit** | Yes | Yes | Native Playwright, **not Safari itself** | Persistent context; provider-dependent | Compatibility testing, not preferred for Google OAuth |
| **Lightpanda 1.x** | Yes, macOS Intel/ARM builds | Inherently headless | CDP / Playwright-compatible paths | Cookies and DOM features, but no full visual browser | Optional DOM/data extraction only; not baseline for OAuth |
| **Brave/Vivaldi/Opera/Arc/other Chromium derivatives** | Varies | Often possible via Chromium flags | Custom executable path / CDP may work, outside Playwright's guaranteed channels | Provider-dependent | Do not build dedicated adapters until an actual requirement exists |
| **Safari.app** | Yes | No supported standard headless Playwright path | `safaridriver`/WebDriver, not Playwright's `webkit` | Normal browser auth | External interactive OAuth only, not autonomous backend |

Chrome's unified headless mode uses the normal browser engine without displaying platform windows; old `--headless=old` was removed from Chrome 132. Playwright's headless shell differs from its `channel="chromium"` new headless behavior. Use the latter for authenticated-site parity. In October 2026 Lightpanda 1.0 has substantial new web standards coverage, but does **not** render actual layouts or screenshots, so it cannot replace Chromium for visual automation or complex sign-in.

**Priority:** `chrome` (CfT) > `chromium` > `firefox` > optional `msedge` / `camoufox` / `cloak` / `webkit` > `lightpanda` only on a known-compatible extraction task.

## 3. What the attached code presently does

### `playwrightauthor`

- `src/playwrightauthor/config.py`: `BrowserConfig.engine` defaults to `chrome`, `headless` defaults to `False`; only `chrome` and `cloak` pass engine validation.
- `src/playwrightauthor/engines/chrome.py`: uses `ensure_browser()` then `connect_with_retry()` / `async_connect_with_retry()` over CDP.
- `src/playwrightauthor/browser_manager.py`: `ensure_browser()` and `launch_browser()` launch Chrome for Testing by calling `launch_chrome_with_retry(...)` **without** forwarding `config.browser.headless` or `config.browser.args`. As written, the Chrome branch does not honor the exposed `headless` setting.
- `src/playwrightauthor/engines/cloak.py`: unlike Chrome, explicitly appends `--headless=new` when configured, but uses `config.browser.debug_port` directly rather than the Chrome engine's per-profile derived port.
- `src/playwrightauthor/browser/process.py`: scans for browser processes; `ensure_browser()` can kill an existing Chrome for Testing process found without the expected debugging port. This can harm an unrelated independent user session.
- `src/playwrightauthor/browser/launcher.py`: launches a detached browser with `--remote-debugging-port` and `--user-data-dir`; special macOS logic strips quarantine and force-ad-hoc-signs the app bundle. Avoid routine signature mutation of installed browser applications.
- `src/playwrightauthor/author.py`: `Browser()` and `AsyncBrowser()` return a Playwright `Browser`; they dynamically attach `get_page()` and reuse the first context and an existing page. They also invoke the interactive task notification on context entry, which should not happen in background mode.

### `virginia-clemm-poe`

- `src/virginia_clemm_poe/browser_manager.py`: constructs `AsyncBrowser(verbose=...)` without an explicit profile, backend, or visibility mode. Its provided `debug_port` argument is not forwarded to PlaywrightAuthor; it relies on default settings.
- `src/virginia_clemm_poe/browser_pool.py`: assumes `browser.contexts[0]` and a browser object extended with `get_page()`. It holds reusable connections but also has an acquisition path creating another manager; audit lifecycle and cleanup.
- `src/virginia_clemm_poe/api.py`: `login_to_poe()` uses a pooled browser page and periodically navigates that same page to a bot URL while the user may be actively completing login. **This can interrupt an OAuth redirect/MFA flow.**
- `src/virginia_clemm_poe/poe_session.py`: extracts Poe and Quora cookies, then saves selected cookie values as JSON in a Poe-specific cookies directory. That file is sensitive and is separate from PlaywrightAuthor's persistent profile.

These findings are based on the two uploaded repository snapshots, not a running checkout. Verify them in the latest source before coding.

## 4. Architecture

### 4.1 Add a new, engine-neutral session API

Keep `Browser()` / `AsyncBrowser()` for backward compatibility, but introduce `BrowserSession()` / `AsyncBrowserSession()` (or the shorter `Session` / `AsyncSession`) as a small context/page-oriented abstraction. A persistent Playwright context need not be wrapped as if it were a `Browser`.

Proposed normalized contract:

```python
async with AsyncBrowserSession(
    engine="chrome",             # chrome, chromium, firefox, ...
    profile="poe-primary",        # identity, independent of backend
    mode="auto",                 # headless, interactive, auto, background
    service="Poe",
    suppress_dialog=True,
) as session:
    page = await session.new_page() # new tab; same authenticated context
    await page.goto("https://poe.com/")
```

Session properties/methods: `session.context` (required), `session.browser` (`Browser | None`), `session.engine`, `session.profile`, `session.mode`, `session.get_page()` (compatibility), `session.new_page()` (recommended), `session.auth_status()`, and `session.close()`. Keep the same normal Playwright `Page` contract for scraper callers.

Internally each backend exposes `start(profile, mode) -> BrowserSessionHandle(context, browser?, owned_process?, close_callback)`. Browser handles for `launch_persistent_context()` are not guaranteed to represent precisely the same contract as CDP-backed Chrome. Do **not** make all engines implement `connect_over_cdp` or pretend all backends can list `browser.contexts`.

### 4.2 Browser adapters

1. `engines/chrome.py` -> existing CfT binary manager, CDP connect, explicit visibility flags and per-profile CDP endpoint. Preserve existing behavior for legacy APIs. A future direct Playwright `launch_persistent_context()` route is possible but not required for the first migration.
2. `engines/chromium.py` -> Playwright `chromium.launch_persistent_context(profile_dir, channel="chromium", headless=(mode != "interactive"))`.
3. `engines/firefox.py` -> Playwright patched `firefox.launch_persistent_context(profile_dir, headless=...)`.
4. `engines/edge.py` -> `chromium.launch_persistent_context(profile_dir, channel="msedge", headless=...)`, gated on installed Edge.
5. `engines/webkit.py` -> `webkit.launch_persistent_context(profile_dir, headless=...)`, gated by smoke tests; not branded Safari.
6. `engines/camoufox.py` -> optional `camoufox.async_api.AsyncCamoufox(persistent_context=True, user_data_dir=..., headless=...)`; separately pin/test Playwright compatibility. Keep its fingerprint stable for a persistent identity rather than changing it every session.
7. `engines/cloak.py` -> keep existing optional adapter but use the common profile/port/visibility/ownership helpers.
8. `engines/lightpanda.py` -> optional CDP adapter only if essential Poe DOM/browser APIs pass tests. Do not advertise as OAuth-ready without provider tests.

Avoid installing every browser. Add extras or on-demand installers (e.g. `uv add "playwrightauthor[camoufox]"` only when appropriate), version-compatible browser downloads, and clear unsupported-engine diagnostics.

### 4.3 Visibility and human attention policy

- `headless`: launch without a native window. **No Dock activation, no notification dialog, no `open -a`, no `page.bring_to_front()`**.
- `interactive`: a dedicated visible profile for a human sign-in, with the normal provider UI, MFA, WebAuthn, and consent.
- `auto`: start headless, evaluate the authenticated target. If unauthenticated, raise `AuthenticationRequired(profile, provider, reason, login_command)` or emit a structured CLI status; do **not** open a window automatically.
- `background`: experimental headed mode, separate from `headless`. A hidden/minimized macOS window can steal focus briefly, affect foreground state, and disrupt Stage Manager/Spaces. Do not promise no interference; test explicit allowlist before enabling. Existing Playwright proposals for non-activating headed Chromium page creation had not shipped as a dependable public option by October 2026.

Do not assume Linux `Xvfb` works natively on macOS. An entirely separate Linux VM or cloud session can run headed browsers on a virtual display, but is a separate optional topology with different session storage and resource trade-offs.

### 4.4 Per-profile ownership and migration

Directory scheme:

```
~/Library/Application Support/playwrightauthor/
  profiles/
    chrome/poe-primary/
    chromium/poe-primary/
    firefox/poe-primary/
    camoufox/poe-primary/
  runtime/
    chrome-poe-primary.json       # pid, port, owner, mode, profile directory
    chrome-poe-primary.lock
```

Separate directory per engine and account. Never point automation to normal Safari, Chrome, or Edge browsing data. Never open the same user-data directory with two simultaneous browser processes. Store the runtime mode and PID against the profile, not just a port. Reject attempts to attach to a mismatched profile, backend, or headed/headless mode. Do not terminate processes without verifying profile path and session ownership. Do not blindly kill an unrelated Chrome for Testing process.

To switch a single profile from headless to interactive: obtain exclusive per-profile lease, ask/await browser users to release pages, close the **owned** browser process cleanly, reopen the same profile visibly, wait for human completion without forced navigation, validate service authorization, close, then restart headless. When a live profile is busy, return `PROFILE_BUSY` rather than corrupt cookies.

For Chrome CDP use a localhost-bound, profile-specific port, preferably dynamically allocated and recorded by the manager; protect against collisions and use `127.0.0.1`. Long-lived externally attached browsers require owner/refcount semantics so closing a client connection does not unexpectedly destroy a different caller's session.

### 4.5 OAuth and session management

Three strategies, ordered by legitimacy/reliability:

1. **First-party OAuth client** (when the target service offers it): use an external normal browser + authorization code/PKCE, a loopback callback/deep link, and token refresh. This requires a registered client and cannot simply be substituted into the Poe website's own Sign in with Google flow.
2. **Website session with interactive sign-in**: human signs in to the target site in a dedicated, headed session, then the same profile is run headlessly. Browser automation of the provider's authentication screen may be rejected; do not automate password, MFA, or CAPTCHA, or attempt to bypass controls.
3. **Saved state fallback**: `BrowserContext.storage_state(indexed_db=True)` for compatible contexts, or persistent profile. Cookies/localStorage/IndexedDB can be restored for testing; sessionStorage, device-bound authentication, WebAuthn, anti-bot clearances and expiring sessions may not transfer. Never promise portability across different browser engines.

Persist browser profile by default; use explicit cookie exports only for Poe's HTTP calls. Do not copy all Google OAuth cookies into another engine. Treat `cf_clearance` as challenge-dependent, not a guaranteed durable credential. Refresh tokens only through the supported provider OAuth flow; never treat website cookie scraping as OAuth refresh-token handling.

Store cookie exports outside the repo, `0700` directories / `0600` files at minimum, preferably secrets in macOS Keychain. Do not log their values or include them in traces/screenshots. Keychain integration is a small scoped enhancement for the separate Poe cookie JSON, not a requirement to manage Chromium's internal cookie DB. Scrub expired cookies and validate real signed-in behavior rather than merely detecting cookie names.

### 4.6 Special requirements for Virginia Clemm Poe

- Expose `browser_engine`, `browser_profile` and `browser_mode` in its settings and CLI. Default to `chrome`, `poe-primary`, `auto/headless`, not the PlaywrightAuthor global default profile.
- Refactor `BrowserManager` to call the new PlaywrightAuthor session API, not directly manage CDP. Its `debug_port` argument should either be used consistently or removed if PlaywrightAuthor owns port allocation.
- Refactor `BrowserConnection` to lease `BrowserSession` + `BrowserContext`, then create a **new page within that authenticated context** per task rather than reusing arbitrary existing tabs. Close only task-owned pages. Pool authenticated *sessions*, not `get_page()` monkeypatched on `Browser`.
- Ensure the updater/scrapers use cached HTTP/API data when available, then headless browser only for a missing field. Avoid launching login UI in ordinary refresh/update runs.
- For `login_to_poe()`, use an explicit **interactive** session and wait for URL/DOM or authenticated request state after login. Do **not** navigate away from the login page every two seconds. Support MFA and email OTP and inspect popup/page events. On timeout keep the state intelligible; do not destroy unrelated tabs.
- Validate login using a stable authenticated Poe endpoint or UI signal plus a meaningful API response, not a specific legacy bot URL (e.g. `Claude-3-Opus`) that might disappear.
- Keep the existing Poe/Quora cookie extraction method as a compatibility path only, record provenance/expiry, and migrate `poe_cookies.json` to a suitably protected store. No cross-browser profile migration automatically.
- Return structured errors: `AUTH_REQUIRED`, `AUTH_REJECTED_BY_PROVIDER`, `PROFILE_BUSY`, `ENGINE_UNAVAILABLE`, `BACKEND_UNSUPPORTED`, `CDP_CONNECTION_FAILED`, and `HEADLESS_SITE_INCOMPATIBLE`. Distinguish provider refusal from ordinary browser failure.

## 6. Implementation sequence and acceptance tests

**Milestone 0: confirm baseline**: run current unit tests, inspect installed Playwright and browser versions, reproduce Chrome `headless` config failing to affect actual launch, and capture the current source as the baseline.

**Milestone 1: fix Chrome without changing the public API**: forward `headless` and arguments through Chrome ensure/launch, use `--headless=new` or equivalent, suppress dialogs when noninteractive, isolate profile/ports, remove destructive process discovery. Add tests for both sync/async entry and actual absence of native windows. Check that regular frontmost app remains frontmost throughout launch, navigate, new-tab, and shutdown.

**Milestone 2: introduce session interface**: `AsyncBrowserSession` and matching sync `BrowserSession`, including per-profile ownership/locking. Keep old `Browser` wrappers. Unit-test CDP session attachment versus browser process ownership.

**Milestone 3: add native engines**: Playwright Chromium and patched Firefox first; Edge and WebKit only if needed. Camoufox optional with pinned compatible dependencies and independent profiles. Lightpanda gated on browser API feature tests, *not* offered as an OAuth solution by default.

**Milestone 4: Virginia Clemm Poe integration**: explicit config; pool refactor; no tab reuse across jobs; interactive login separated from scheduled scrape; cookie store hygiene.

**Milestone 5: provider matrix and regression:** On actual macOS Intel and Apple Silicon hardware, test service login and subsequent new-process headless reuse with **test accounts** where permitted. Test direct Poe email/OTP and its actual enabled federated login methods; Google OAuth acceptance, redirects, MFA, logged-out state, expired cookies, device revalidation; Chrome, Firefox, and Camoufox separately. Observe success/failure, do not assume provider behavior.

| Acceptance scenario | Required result |
|---|---|
| Headless Chrome from cold launch | Never creates an interrupting visible window or activates browser UI |
| Headless launches while editor/terminal is active | Frontmost app, typing target, Stage Manager/Spaces unchanged |
| Login required in `auto` mode | Structured `AUTH_REQUIRED`; no browser window |
| Explicit login | Visible dedicated profile, no script interference during OAuth/MFA |
| Restart after interactive login | Reuses authorized site session when provider permits |
| Firefox/CDP backends | Same `Page`-based client workflow without assuming a CDP API on Firefox |
| Simultaneous jobs, same profile | Safely pooled or serialized, no simultaneous profile writers |
| Simultaneous jobs, other profiles | No cross-account cookies or process termination |
| Login callback fails or expires | Clear error, no cookie export from another identity |
| Provider refuses automated login | Do not spoof/bypass; offer external OAuth or approved manual sign-in route |
| Poe scrape succeeds then one tab fails | Remaining jobs and profile survive; close only task-owned resources |
| Lightpanda selected for screenshot | Explicit unsupported error or configured full-browser fallback |

No live OAuth login or macOS focus-control tests were executed during preparation of this specification.
